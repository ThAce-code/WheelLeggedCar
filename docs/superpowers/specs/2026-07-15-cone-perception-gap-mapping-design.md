# 锥桶识别、跟踪与间隙地图设计

## 1. 目标

为 CYT4BB7 轮腿车增加一套基于 MT9V03X 单目灰度相机的感知系统。车辆去程先直行至掉头区，同时建立静态锥桶地图；掉头后按“掉头区到发车区”的顺序依次穿过相邻锥桶形成的全部间隙。

本设计负责：

- 单帧锥桶检测；
- 像素接地点到局部地面坐标的投影；
- 静态锥桶跟踪、合并和编号；
- 去程锥桶排序及 `N-1` 个间隙生成；
- 返程当前间隙目标输出；
- 感知失效检测及安全降级信号。

本设计不负责底盘路径跟踪、转向控制、平衡控制、GPS 导航和掉头动作。CM7_0 继续拥有车辆执行机构和最终安全停车权限。

## 2. 已确认约束

### 2.1 硬件与任务

- 主控：CYT4BB7，CM7_0 与 CM7_1 均运行在 250 MHz。
- 相机：MT9V03X 灰度全局快门相机，18 线模块接口。
- 镜头：商品标称 120°，标称几何畸变小于 1%；固件不得把 120°直接当作水平视场角。
- 运行分辨率与帧率：`188x120 @ 50 FPS`。
- 已实测：WiFi-SPI 能将实时图像送至逐飞助手，并可保存 BMP。
- 车辆速度：0.5–1.0 m/s。
- 两锥桶最小间距：1.5 m。
- GPS 为普通 GPS，仅用于长距离方向和掉头区辅助，不参与锥桶厘米级定位。
- 锥桶排列不要求共线。

### 2.2 已选算法路线

采用“灰度多特征融合 + 时序跟踪 + 地面几何投影”。不采用神经网络，原因是当前数据集、算力、模型存储和部署验证成本均不合适；不采用单阈值或单轮廓方案，原因是曝光、地砖、阴影和车辆结构会产生大量相似目标。

## 3. 总体架构

### 3.1 双核职责

CM7_0 拥有已验证的 MT9V03X 采集服务；CM7_1 拥有视觉感知和非关键调试显示：

```text
CM7_0: MT9V03X 采集
  -> 双槽跨核帧发布（188x120 灰度帧、sequence、capture_ms）

CM7_1: 获取最新完整帧
  -> 图像质量检查与ROI生成
  -> 单帧候选检测和打分
  -> 接地点投影
  -> 静态锥桶跟踪/地图
  -> 间隙生成与当前目标
  -> 共享快照
```

CM7_0 保持实时控制与安全职责：

```text
IMU + 轮速 + 腿高
  -> 车辆姿态/局部里程计
  -> 共享位姿快照

感知目标快照
  -> 任务状态与目标选择检查
  -> 底盘/平衡控制
  -> 失效时减速或停车
```

WiFi-SPI 不属于比赛关键链路。它只在调试模式下抽帧显示、保存 BMP、发送诊断数据；无线卡顿不得阻塞相机采集和识别。

### 3.2 共享内存

复用已验证的 8 KB、无初始化 `intercore_shared_layout`，不再新增 `.perception_shared` 链接段。原始图像继续只经既有的 64 KB 双槽图像平面传输；控制区只传结构化快照，不传跨核指针。

共享区包含：

- CM7_0 -> CM7_1：双缓冲 `PoseSnapshot`，包括序号、时间戳、局部位姿、姿态、轮速、腿高、有效标志和 CRC；
- CM7_1 -> CM7_0：双缓冲 `PerceptionSnapshot`，包括状态、当前 `GapTarget`、地图摘要、诊断计数、时间戳和 CRC；
- 两类快照使用 `intercore_shared_layout.reserved` 的明确、带版本的子布局；扩容时同时更新 `INTERCORE_PROTOCOL_VERSION`、布局大小检查和两核静态 ABI 测试；
- 每个方向均采用“写非活动槽 -> 内存屏障 -> 发布序号”的协议；
- 读者读取前后两次序号，序号一致且 CRC 正确才接受；
- 任何超龄、序号回退或 CRC 错误都使快照失效。

## 4. 时间基准与坐标系

### 4.1 时间同步

相机帧在 CM7_0 的采集时刻记录 `capture_ms` 并随双槽帧发布。CM7_0 以至少 100 Hz 发布位姿快照。CM7_1 对采集时刻前后的两个位姿样本做线性插值；姿态使用小角度插值或单位四元数归一化插值。

全局快门意味着同一帧像素共享曝光时刻，不需要逐行时延补偿。“候选内部取 3–5 个高度截面”只用于检查锥桶形状，不是滚动快门扫描。

### 4.2 坐标系

- 相机系 `C`：`x` 向图像右侧，`y` 向图像下方，`z` 向镜头前方；
- 车体系 `B`：`x` 向车头，`y` 向车体左侧，`z` 向上；
- 局部世界系 `W`：原点为发车时车辆位置，`z` 向上，地面为 `z=0`；
- 纵向单位向量 `e_long` 指向发车区到掉头区。

记 `R_ab` 为把 `b` 系向量变换到 `a` 系。运行时：

```text
R_wc = R_wb(t) * R_bc
p_wc = p_wb(t) + R_wb(t) * t_bc
```

`R_bc` 和 `t_bc` 来自安装外参标定。腿长变化时相机高度不能写死；`p_wb(t)` 的高度由当前腿高、车体几何和安装偏置计算。

## 5. 相机标定与图像采集

### 5.1 标定链路

OpenCV 只在电脑端离线运行：

```text
MT9V03X -> CYT4BB7 -> WiFi-SPI -> 逐飞助手保存BMP
                                      -> PC OpenCV标定
                                      -> 参数量化后写回固件
```

优先使用 `376x240` 单帧标定模式；如果相机驱动只能稳定提供 `188x120`，则直接在运行分辨率标定。禁止使用被软件窗口缩放后的屏幕截图，必须使用逐飞助手保存的原始尺寸 BMP。

使用 9x6 内角点棋盘格，方格边长实测后写入标定命令。采集 20–30 张有效图像，棋盘覆盖画面中心、四角和边缘，并包含水平、俯仰、偏航方向的不同角度。图像模糊、棋盘区域过曝或角点靠近裁剪边缘时拒绝该帧。

同时拟合普通 Brown-Conrady 模型和鱼眼模型。若普通模型在全部图像上的 RMS 重投影误差不超过 0.30 像素、边缘残差无方向性偏差，则选普通模型；否则选鱼眼模型。标定文件必须记录：

- 分辨率；
- 内参 `fx, fy, cx, cy`；
- 畸变模型和系数；
- 每张图像及总体重投影误差；
- 标定日期和相机模块标识。

实际视场角由内参计算，而不是复制商品页数值：

```text
HFOV = 2 * atan(W / (2*fx))
VFOV = 2 * atan(H / (2*fy))
```

如果标定分辨率到运行分辨率只是等比例缩放，则 `fx/fy/cx/cy` 按横纵比例缩放，畸变系数不变；只要存在裁剪或非等比例缩放，就必须按实际成像链路重新换算并验证。

### 5.2 外参与地面验证

相机装车后，在平地布置至少六个已知地面点，求取 `R_bc`、`t_bc`，并用未参与求解的点验证像素到地面投影。改变腿高后重复验证，确认动态高度模型正确。缺少有效内参、外参、腿高零点或验证结果时，感知状态停留在 `READY`，不得输出可执行间隙目标。

### 5.3 曝光策略

全局快门消除了几何错位，但不会消除过曝和运动模糊。调试画面已经证明链路可用，同时显示当前室内画面有明显高光饱和，因此加入以下质量门限：

- 启动时允许自动曝光稳定；
- 标定拍照时，自动曝光稳定后锁定曝光与增益；
- 运行时允许受限自动曝光，但设置最大曝光时间，避免 1.0 m/s 下目标边缘明显拖影；
- 每帧统计过暗、过亮比例和局部对比度；质量不合格时降低检测置信度，而不是放宽形状阈值；
- 最终曝光上限通过室外 0.5 m/s 和 1.0 m/s 录像确定并固化为配置。

## 6. ROI 与 IMU 地平线

### 6.1 IMU 地平线

世界地面法向为 `n_w=[0,0,1]^T`，相机系法向为：

```text
n_c = R_wc^T * n_w
```

在理想归一化像平面中，地平线满足：

```text
l = K^-T * n_c
v_h(u) = -(l_x*u + l_z) / l_y
```

滚转主要改变地平线斜率，俯仰主要改变纵向位置，偏航在平地上基本不改变地平线。公式使用的是相机帧 VSYNC 时刻的插值姿态，不是最新 IMU 样本。

检测在原始畸变图像上进行。每帧先在无畸变平面计算地平线，再用标定模型把 188 个列采样点映射回原始像素，形成 `v_h[u]` 曲线；不对整帧做重采样。

### 6.2 三层 ROI

1. 地面发现区：每列从 `v_h[u]-margin` 开始，`margin` 初值 3–5 像素，并根据标定、姿态和车体振动不确定度增大；起点必须略高于预测地平线，以免漏掉远处锥桶尖端。
2. 跟踪预测窗：根据已有锥桶地图和当前车辆位姿预测图像位置，窗口相对上一帧包围盒扩大 20–30%，每帧处理。
3. 全局发现：完整地面 ROI 每两帧处理一次，即 25 Hz；跟踪窗仍保持 50 Hz。

地平线不确定带内的候选只形成方位暂定目标，不立即投影进地图。车体自身固定遮挡区域使用相机坐标中的静态多边形掩膜排除。

## 7. 单帧锥桶检测

### 7.1 一次顺序遍历

检测不逐行等待相机，也不生成完整 Sobel 图。对 ROI 做一次顺序遍历：

1. 用滚动行缓冲计算局部均值和对比度；
2. 生成亮带、暗区和边缘响应；
3. 以行程编码记录连续像素段；
4. 把相邻行的重叠段合并成连通候选；
5. 在候选结束时累计面积、包围盒、亮暗分布、中心和边缘统计。

使用 Q8/Q15 定点数、行列查找表和固定容量数组；运行时禁止动态内存。

### 7.2 候选形状截面

在候选包围盒的归一化高度上取水平截面，检查宽度由上到下总体增大、中心位置稳定：

- 高度小于 12 像素：3 个截面；
- 高度 12–24 像素：4 个截面；
- 高度大于 24 像素：5 个截面。

截面只是候选内部的几何采样，不会再次遍历整幅图像。

### 7.3 初始评分

总分量化到 0–255：

| 特征 | 权重 |
|---|---:|
| 上窄下宽的锥形趋势 | 77/256 |
| 中部亮带/白带的相对灰度结构 | 64/256 |
| 左右对称与截面中心稳定 | 38/256 |
| 高宽比和竖直性 | 26/256 |
| 底部接地边与底座结构 | 26/256 |
| 相对局部背景的对比度/边缘 | 25/256 |

`score >= 166` 为候选，`score >= 204` 为高置信候选。这些是数据采集前的起始权重，不是永久经验常数。标注数据集建立后，使用逻辑回归或网格搜索优化权重和阈值，再量化回 8 位整数。

重叠候选用底部接地点、包围盒重叠率和得分做非极大抑制。候选最大数量固定为 32，超出时只保留高分且空间分散的候选，并增加溢出诊断计数。

## 8. 像素接地点到地面坐标

使用锥桶底部中心像素 `(u_b,v_b)`，而不是包围盒中心。先把该点变换为无畸变像素 `(u_u,v_u)`：

```text
q_u = [u_u, v_u, 1]^T
d_c = normalize(K^-1 * q_u)
d_w = R_wc * d_c
```

射线与地面 `z=0` 的交点为：

```text
lambda = -p_wc,z / d_w,z
p_w = p_wc + lambda * d_w
```

仅当 `lambda>0` 且 `|d_w,z|` 足够大时接受交点。接近地平线时，距离对像素和俯仰误差极度敏感，因此只保留方位信息。

每个地面观测附带 2x2 协方差 `R_j`。协方差由底部像素误差、IMU 俯仰/滚转误差、腿高误差、内外参误差的一阶传播或离线查表获得；距离越远、越接近地平线，协方差越大。

## 9. 静态锥桶跟踪与地图

锥桶在局部世界系中静止，车辆位姿随 IMU 和轮速变化。数据流固定为：

```text
IMU + 轮速 + 腿高 -> 车辆位姿预测
已有地图 + 车辆位姿 -> 图像/地面预测观测
当前检测 + 预测观测 -> 门控关联
关联结果 -> 轨迹更新 -> 确认/合并 -> 地图
```

感知地图不反向修改 IMU 原始姿态。返程看到两个以上已知锥桶时，可以输出低频局部位姿修正建议，但 CM7_0 决定是否融合。

### 9.1 数据关联

对观测 `z_j` 和轨迹预测 `x_i`：

```text
e = z_j - x_i
D^2 = e^T * (P_i + R_j)^-1 * e
```

使用二维 95% 卡方门限 `D^2 <= 5.99`，并增加与距离相关的最大欧氏距离门限。地图最多 32 个锥桶，采用按距离排序的贪心最近邻即可；不引入匈牙利算法。

静态目标更新：

```text
K = P * (P + R)^-1
x_new = x + K * (z - x)
P_new = (I - K) * P
```

### 9.2 生命周期

- 普通候选在最近 5 帧命中至少 3 帧后确认；
- 远处小目标在最近 6 帧命中至少 4 帧后确认；
- 连续漏检 1–7 帧：保留预测；
- 连续漏检 8 帧：标记为仅预测，不用于新建间隙；
- 连续漏检 20 帧：只删除未确认轨迹；
- 已确认地图锥桶离开视场后仍保留到本次任务结束。

重复轨迹仅在距离小于 0.25–0.35 m、协方差椭圆重叠且合并后不违反 1.5 m 最小间距约束时合并。保留历史更长、协方差更小的 `cone_id`。

## 10. 间隙地图

发车时记录局部起点。去程用里程计位移和中值航向持续估计纵向方向，普通 GPS 只用于长基线方向校核。收到 CM7_0 的掉头锁定事件时：

```text
e_long = normalize((p_turn - p_start)_xy)
s_i = p_i dot e_long
```

若起终位移不足以稳定求方向，则使用去程稳定阶段的中值车头方向。按 `s_i` 从小到大排序得到 `C1...CN`，相邻锥桶形成 `N-1` 个间隙：

```text
G_i = (C_i + C_(i+1)) / 2
```

掉头锁定后冻结 `cone_id`、排序和 `gap_id`；锥桶位置允许继续小幅优化，但已通过间隙不得重新排序。返程按照 `G_(N-1)` 到 `G_1` 的顺序执行。

每个间隙输出：

- 左右 `cone_id`；
- 门线中心；
- 指向发车区的通过法向；
- `approach = center - 0.6 m * n_pass`；
- `exit = center + 0.6 m * n_pass`；
- 锥桶间距、有效净宽、置信度和数据年龄。

有效净宽为“锥桶间距 - 车宽 - 2x安全边距”。车宽和安全边距必须由实车配置提供；净宽不足时输出 `GAP_TOO_NARROW`，不得输出可执行目标。

穿越确认同时满足：

- 车辆相对门线的有向距离从小于 `-0.20 m` 变为大于 `+0.20 m`；
- 车体中心位于两锥桶安全边界之间；
- 当前仍是同一个 `gap_id`；
- 连续 2–3 个 20 Hz 更新满足条件。

## 11. 感知状态机与输出

状态机：

1. `BOOT`：初始化相机、共享区和算法状态；
2. `READY`：等待有效标定、姿态稳定和连续 5 帧有效图像；
3. `OUTBOUND_MAP`：去程检测、跟踪和建图，不输出穿越目标；
4. `TURN_LOCK`：响应 CM7_0 掉头事件，冻结排序及间隙；
5. `RETURN_GAPS`：按远到近输出当前间隙；
6. `FINISH`：全部 `N-1` 个间隙已确认通过；
7. `SAFE_STOP`：关键输入超龄、共享数据损坏或目标长期无效。

`GapTarget` 至少包含：

```text
seq, timestamp_ms, state, valid, gap_id,
left_cone_id, right_cone_id,
approach_xy_body, center_xy_body, exit_xy_body,
gap_width_m, clearance_m, confidence, age_ms, flags
```

CM7_1 以 20 Hz 发布目标。CM7_0 仅接受序号递增、CRC 正确、`valid=1` 且未超龄的目标。

## 12. 实时性与内存预算

`188x120` 共 22,560 像素。250 MHz 下每像素 20/40/60/80 周期分别约为 1.8/3.6/5.4/7.2 ms。设计目标：

- 常规 ROI 处理 12k–18k 像素；
- 单帧典型 4–8 ms；
- P99 不超过 15 ms；
- 跟踪窗 50 Hz；
- 全局发现 25 Hz；
- 地图/间隙目标 20 Hz；
- 无动态内存，固定容量 32 个轨迹。

内存预算：

- 双灰度帧：45,120 B；
- 二值/状态掩膜：约 2,820 B；
- 行缓冲、行程、候选和轨迹：不超过 32 KB；
- 标定参数、地平线列数组和固定点查表：不超过 16 KB；
- 算法静态内存目标不超过 96 KB，不含栈；
- 376x240 标定模式只使用单帧约 90 KB，并暂停实时识别和连续图传。

逐飞助手显示的 FPS 和字节率仅用于调试，不作为 CM7_1 本地算法周期的时钟源。

## 13. 故障与降级

- IMU 姿态年龄大于 30 ms：停止地面投影，立即使 `GapTarget` 无效；
- 轮速年龄大于 100 ms：停止更新车辆平移位姿；
- 相机超过 100 ms 无新帧：只允许已确认地图短时预测并降低置信度；
- 相机超过 300 ms 无新帧：停止输出可执行目标；
- 相机恢复后连续 5 帧有效才重新放行；
- 当前间隙没有两个可靠锥桶或地图顺序存在歧义：不输出目标；
- 连续 3 帧处理超过 20 ms：暂停全局发现，只处理跟踪窗；
- 降载后仍超时、共享 CRC 错误或序号异常：进入 `SAFE_STOP`；
- CM7_0 对任何无效或超龄目标执行减速/停车，绝不沿用最后一个目标无限行驶。

## 14. 数据集与参数训练

建立三类数据：

1. 内参 BMP：棋盘格原始尺寸图像；
2. 检测数据：不同距离、背景、光照、锥桶姿态和遮挡的灰度帧，逐帧标注包围盒和底部接地点；
3. 同步回放数据：图像序号、VSYNC 时间、IMU、轮速、腿高、车辆状态和实测锥桶坐标。

检测评分权重、阈值、距离协方差和曝光门限只能从训练子集确定，验收指标必须在独立验证子集和实车场地上计算。禁止使用验收场景逐帧手工调参后再报告同一场景结果。

## 15. 验证与验收

### 15.1 分层验证

1. PC 静态测试：标定模型、畸变点变换、地平线、射线地面交点、马氏距离、排序和间隙几何；
2. 录像回放：检测、跟踪、地图和状态机使用相同输入应得到确定性结果；
3. CM7_1 开环：相机在线但车辆不动，只记录候选、耗时、溢出和共享快照；
4. 低速实车：0.5 m/s 去程建图和返程目标输出，CM7_0 先只记录不执行；
5. 闭环穿越：通过安全门限后允许底盘跟踪间隙目标；
6. 速度升级：0.5 m/s 连续通过后再测试 1.0 m/s。

### 15.2 首轮验收门限

- 可靠识别范围：0.5–4.0 m；4–6 m 只能作为暂定目标；
- 可靠范围 Precision 不低于 98%，Recall 不低于 95%；
- 地面位置误差：3 m 内 P95 不超过 0.20 m，3–5 m P95 不超过 0.35 m；
- 间隙中心误差 P95 不超过 0.20 m；
- 完整去返程中锥桶排序错误为 0，确认后的 ID 错换每圈为 0；
- 单帧耗时典型 4–8 ms，P99 不超过 15 ms；
- 输入超龄后在规定时限内使目标无效，无继续使用陈旧目标的情况；
- 0.5 m/s 连续 10 圈无漏穿、错穿和碰桶后，才进入 1.0 m/s 验证；
- 1.0 m/s 连续 10 圈无漏穿、错穿和碰桶，才判定任务感知通过。

## 16. 模块边界

计划新增的固件模块：

- `camera_capture_producer`：CM7_0 采集、VSYNC 时间戳和双槽帧发布（既有模块，不重写）；
- `camera_frame_consumer`：CM7_1 获取最新帧、调用感知流水线和可丢弃的 WiFi-SPI 调试显示；
- `perception_calibration`：内外参、单点去畸变和坐标变换；
- `perception_roi`：IMU 地平线、发现区和预测窗；
- `perception_detector`：顺序扫描、连通候选和评分；
- `perception_projection`：接地点投影和观测协方差；
- `perception_tracker`：关联、静态滤波、生命周期和地图；
- `perception_gap`：排序、间隙、穿越确认和状态机；
- `perception_intercore`：既有跨核 ABI 中的位姿/感知快照、序号、屏障和 CRC；
- CM7_0 侧 `perception_client`：快照校验、超龄处理和目标适配。

每个模块只通过头文件公开固定结构和函数，内部缓冲区保持私有。相机驱动、检测器和地图不得直接调用底盘执行机构。

## 17. 兼容性与安全边界

- 不修改现有 IMU 轴向定义、平衡控制周期、舵机轨迹、轮速闭环和电机安全限幅；
- 相机采集和帧发布保留在 CM7_0；感知、WiFi-SPI 与调试任务落在 CM7_1；
- WiFi-SPI 调试发送必须可编译关闭，关闭后不改变算法输出；
- 共享内存和新中断的优先级不得高于平衡和执行机构关键中断；
- 任一感知异常的默认行为是“无目标”，而不是猜测目标；
- 实现阶段必须先完成离线回放和开环输出，再授权闭环车辆运动。
