# 定点排雷 GPS、视觉与旋转控制设计

**日期：** 2026-07-16

**分支：** `codex/cone-perception-gap-mapping`

**适用硬件：** CYT4BB7、TAU1201、前下视 MT9V03X、LSM6DSV16X、左右轮反馈

## 1. 目标

完成定点排雷比赛任务：车辆从发车区出发，按任意顺序依次进入预先铺设的若干个 1 m × 1 m 白色雷区，在每个雷区内原地旋转至少两圈，旋转期间车轮不得越过白色边框；完成全部雷区后前往掉头区并返回发车区。

本设计采用以下已确认约束：

- 允许赛前测量并录入发车点、雷区、掉头区和返航点坐标；
- 现有 GNSS 模块为 TAU1201，不依赖 RTK；
- 相机采用前下视安装；
- 左右车轮最外侧宽度约 20 cm；
- UART0 继续用于 CM7_0 的 VOFA+ 遥测和调试命令；
- TAU1201 使用 CM7_1 的 UART2；
- GPS 只负责全局粗引导，不能负责雷区内边界控制。

## 2. 核心决策

采用分层定位与控制：

1. TAU1201 根据赛前测得坐标把车辆引导到雷区附近；
2. 距目标约 1–2 m 时降速并切换到前下视视觉；
3. 相机识别白色方框，完成对准、进框和居中；
4. 框内位置由视觉、IMU 和轮速短时里程共同维持，GPS 退出控制；
5. IMU 连续解包偏航角并累计旋转量，左右轮反馈确认车辆真实旋转；
6. 完成后退出雷区，重新启用 GPS 粗引导；
7. 任一关键定位源失效时采用停车优先策略，不盲目续行。

TAU1201 标称亚米级，但雷区白框内侧约 80 cm。车辆轮宽约 20 cm，车体中心的理论横向余量约为 ±30 cm，因此普通 GNSS 无法保证车轮不越界。

## 3. 核心与外设职责

### 3.1 CM7_0 实时控制域

CM7_0 负责：

- IMU 姿态、角速度和车身平衡；
- 左右轮速度、短时里程和轮速健康；
- 执行经过验证的前进速度与转向速度请求；
- 运动限幅、命令超时、平衡和执行器安全；
- 通过现有共享内存发布车体短时位姿；
- 通过 UART0 发送 VOFA+ 遥测并接收维护命令。

CM7_0 不初始化相机、GNSS 或 Wi-Fi，不直接执行任务规划。

### 3.2 CM7_1 感知与任务域

CM7_1 负责：

- 通过 UART2 接收 TAU1201 NMEA 数据；
- 解析、校验并生成不可变 GNSS 快照；
- 将 WGS-84 经纬度转换为发车点局部坐标；
- 前下视相机采集与白框几何检测；
- 保存场地图、目标完成状态和任务状态机；
- 融合 CM7_0 短时位姿、GPS 粗位置和视觉局部修正；
- 通过现有跨核命令接口发布归一化运动请求。

CM7_1 不直接写电机、舵机、平衡或底盘私有状态。

## 4. 赛前场地图

每个预设点使用以下记录：

```c
typedef struct
{
    uint16 point_id;
    uint8 point_type;
    uint8 enabled;
    double latitude_deg;
    double longitude_deg;
    float local_x_m;
    float local_y_m;
    float approach_x_m;
    float approach_y_m;
    float approach_heading_rad;
} mine_field_point_struct;
```

`point_type` 至少包含：

- `START`：发车点和局部坐标原点；
- `MINE`：雷区中心；
- `TURN`：掉头区参考点；
- `FINISH`：返航停车点。

每个雷区额外保存完成标志、固定访问顺序和推荐退出方向。比赛顺序没有规定，赛前根据实测坐标生成一条较短且易复现的固定路线；比赛中不做复杂动态路线优化。

### 4.1 测点方法

1. 使用比赛时同一块 TAU1201 和同一根天线；
2. 天线放在目标中心，并保持与装车后相近的高度和方向；
3. 在开阔环境等待定位稳定；
4. 以 10 Hz 连续采样 1–2 分钟；
5. 丢弃无效帧、HDOP 超限帧和明显离群点；
6. 对剩余坐标做稳健平均并记录离散程度；
7. 按顺序测量发车点、雷区中心、掉头点和返航点；
8. 尽量在比赛前较短时间内测量，降低普通 GNSS 随时间产生的整体漂移。

雷区中心 GPS 坐标仅用于粗定位。实际进框中心由相机重新测量。

## 5. GNSS 数据模型

`sensor_gnss` 生成如下逻辑快照：

```c
typedef struct
{
    uint32 sequence;
    uint32 timestamp_ms;
    double latitude_deg;
    double longitude_deg;
    float local_x_m;
    float local_y_m;
    float speed_mps;
    float course_deg;
    float hdop;
    float position_sigma_m;
    uint16 satellite_count;
    uint8 fix_valid;
    uint8 fix_quality;
    uint32 checksum_error_count;
    uint32 timeout_count;
} gnss_snapshot_struct;
```

当前逐飞 GNSS 库已经解析 RMC 的定位有效、经纬度、速度和地面航向，以及 GGA 的卫星数和高度。项目级封装必须补充：

- GGA Fix Quality；
- HDOP；
- 本地接收时间和数据龄期；
- 连续序号；
- 校验错误、超时和无效定位计数；
- 位置跳变检测；
- 局部平面坐标和位置不确定度。

### 5.1 有效性门限

初始门限为：

- 数据龄期不超过 300 ms；
- 参与定位卫星不少于 8 颗；
- HDOP 不大于 2.0；
- RMC 和 GGA 定位状态有效；
- 位置变化不超过由车辆最大速度、采样间隔和容差计算的跳变上限；
- 连续 3–5 帧有效后才允许从 GPS 故障恢复。

这些门限必须通过现场日志验证后再调整。GPS 无效时，不允许继续长距离纯里程计导航。

### 5.2 经纬度转换

发车点作为局部原点。所有目标坐标在任务启动前转换到局部东-北平面坐标。运行控制只使用相对原点的 `local_x_m/local_y_m`，避免单精度浮点直接保存绝对经纬度造成明显精度损失。

## 6. 白框视觉数据模型

`mine_vision` 输出：

```c
typedef struct
{
    uint32 sequence;
    uint32 timestamp_ms;
    float frame_center_x_m;
    float frame_center_y_m;
    float frame_yaw_rad;
    float distance_front_m;
    float distance_rear_m;
    float distance_left_m;
    float distance_right_m;
    float confidence;
    uint8 frame_valid;
    uint8 visible_edge_mask;
} mine_frame_snapshot_struct;
```

处理流程：

1. 对前下视图像进行亮度归一化和白色胶带候选提取；
2. 使用相机标定参数和地面单应性把像素转换为地面坐标；
3. 拟合互相垂直的白色边线；
4. 利用 1 m 方框尺寸、线宽和几何一致性排除赛道线与局部反光；
5. 输出车体相对白框中心的位置、角度、四边距离和置信度；
6. 进入框内后冻结雷区局部坐标系，部分边线暂时不可见时使用已确认方框模型和短时里程继续估计；
7. 视觉重新获得有效边线后只做有界位置修正，防止坐标突跳。

视觉测距验收目标为中心和边线距离误差不超过 5 cm。

## 7. 任务状态机

```text
WAIT_START
  -> GPS_CRUISE
  -> VISION_SEARCH
  -> FRAME_APPROACH
  -> FRAME_CENTER
  -> ROTATE_IN_FRAME
  -> FRAME_EXIT
  -> GPS_CRUISE（下一个雷区）
  -> TURN_APPROACH
  -> RETURN_CRUISE
  -> FINISH

任意状态 -> SAFE_STOP
```

### 7.1 GPS_CRUISE

- 目标为当前雷区的 `approach_x/y`；
- 使用 GPS 粗位置和 CM7_0 短时位姿控制低速接近；
- 距接管点约 1–2 m 时降速并进入 `VISION_SEARCH`；
- GPS 不直接判定车辆已经进入雷区。

### 7.2 VISION_SEARCH

- 停车或以受限低速、小角度搜索白框；
- 只有连续多帧方框有效后才进入 `FRAME_APPROACH`；
- 搜索时间和搜索范围受限，超限进入 `SAFE_STOP`。

### 7.3 FRAME_APPROACH

- 推荐速度为 0.1–0.2 m/s；
- 根据方框中心误差和角度误差对准并进入；
- 视觉置信度不足立即停车；
- 不使用 GPS 位置做边界判定。

### 7.4 FRAME_CENTER

- 速度低于 0.1 m/s；
- 将车辆中心控制到方框中心 ±10 cm；
- 连续多帧满足位置、角度和边界置信度后停车确认；
- 确认完成后进入 `ROTATE_IN_FRAME`。

### 7.5 ROTATE_IN_FRAME

- 锁定一个旋转方向；
- 左右轮使用相反方向的速度目标；
- 平移速度目标为零；
- 相机持续修正中心位置；
- IMU 连续解包偏航角并累计选定方向上的有效角度；
- 左右轮必须保持反向运动，反向回摆不计入有效完成角度；
- 规则要求不少于 720°，软件完成门限设为 750°；
- 完成后对准预设退出方向。

### 7.6 FRAME_EXIT

- 以视觉低速驶出；
- 相机确认车辆越过方框外沿；
- 仅在确认退出后标记雷区完成；
- 返回 GPS 粗导航。

### 7.7 TURN 与 RETURN

- 所有雷区完成后前往掉头区；
- 返航使用预设回程点和同一套 GPS 有效性门控；
- 接近发车区后使用场地白线或已知入口几何做最终停车修正，不能只依赖普通 GNSS 判定精确停车点。

## 8. 边界安全

白框外边长为 1 m，胶带宽约 10 cm，内侧可用宽度约 80 cm。车轮外宽约 20 cm，车体中心理论上应距离任一内边线至少 10 cm 才能保证轮迹不越界。

采用更保守的门限：

- 正常居中目标：中心误差不超过 10 cm；
- 任一预测车轮距内边线小于 15 cm：减速并向中心纠偏；
- 任一预测车轮距内边线小于 10 cm：立即停车；
- 视觉无效或位置不确定度过大：立即停车；
- 停车后只允许向方框中心方向执行受限纠偏；
- 未重新获得可靠视觉边界前禁止继续旋转。

边界判定使用估计的左右轮接地点，而不是仅使用车体中心。

## 9. 模块边界

新增模块：

- `sensor_gnss.c/.h`：TAU1201 初始化、NMEA 解析封装和 GNSS 快照；
- `local_position.c/.h`：经纬度转局部坐标、有效性门控和短时融合；
- `mine_field_map.c/.h`：场地点、固定路线和完成状态；
- `mine_vision.c/.h`：白框检测、地面投影和边线距离；
- `mine_rotation.c/.h`：偏航角解包、旋转方向锁定和圈数确认；
- `mine_mission.c/.h`：任务状态机和降级策略。

复用现有模块：

- 相机跨核传输和最新帧获取；
- 感知共享内存与版本化快照机制；
- `motion_command_router`；
- CM7_0 IMU、轮速、平衡和安全模块；
- 非阻塞 VOFA+ 遥测服务。

排雷模块不得直接调用电机或舵机执行器接口。

## 10. UART 与 VOFA+ 遥测

外设所有权保持为：

```text
UART0 -> CM7_0 -> VOFA+ 遥测和维护命令
UART2 -> CM7_1 -> TAU1201 NMEA
CM7_1 -> 共享内存 -> CM7_0 -> UART0/VOFA+
```

当前 VOFA+ 使用 460800 baud、JustFloat 协议、55 个 float、100 Hz。新增任务遥测时不向 JustFloat 数据流插入原始 NMEA 文本。

建议提供两种固定通道布局：

- 平衡调试布局：保留当前 55 通道和 100 Hz；
- 排雷任务布局：约 40–60 通道、50 Hz，包含 GPS、视觉、任务和安全信息。

任务布局至少包含：

```text
gps_valid
gps_local_x_m
gps_local_y_m
gps_satellite_count
gps_hdop
gps_age_ms
gps_speed_mps
gps_course_deg
target_dx_m
target_dy_m
target_distance_m
current_mine_id
mission_state
vision_valid
vision_center_error_x_m
vision_center_error_y_m
minimum_wheel_clearance_m
rotation_accumulated_deg
fault_reason
```

GPS 本身最多 10 Hz，VOFA+ 更高刷新率只重复最新快照。`gps_age_ms` 用于判断是否收到新数据。

绝对经纬度不得直接压缩成单个 `float` 用于测点保存。测点使用 `double` 或原始 NMEA/CSV；运行遥测使用局部米制坐标。

## 11. 故障与恢复

| 故障 | 响应 |
|---|---|
| GPS 在粗导航阶段失效 | 减速停车，等待连续多帧恢复 |
| 到达预测位置但找不到白框 | 受限搜索，超时安全停车 |
| 进框时视觉置信度不足 | 立即停车，不盲目前进 |
| 框内旋转时视觉丢失 | 立即停止旋转，重新识别后继续 |
| IMU 无效或偏航数据超时 | 立即停止 |
| 左右轮未形成反向运动 | 不累计旋转角并停车检查 |
| 跨核命令或快照超时 | CM7_0 清零运动目标 |
| 位置跳变或非有限值 | 拒绝该帧并计数 |
| CM7_0 安全或平衡故障 | 执行器安全策略优先，任务进入安全停止 |

雷区只在以下条件全部满足后标记完成：

- 有效累计旋转不少于 750°；
- 旋转过程没有确认的越界事件；
- 视觉或融合位姿没有持续失效；
- 车辆成功退出该雷区。

## 12. 验证与验收

### 12.1 静态与主机测试

- NMEA RMC/GGA 正常、校验失败、截断、超时和无效定位解析；
- 经纬度到局部坐标转换；
- GPS 跳变与连续恢复门控；
- 偏航角跨 ±180° 解包；
- 反向回摆不增加有效旋转量；
- 场地图访问顺序和完成状态；
- 白框几何一致性、部分边线和错误尺寸拒绝；
- 跨核快照版本、大小、CRC 和超时处理；
- VOFA+ 固定帧长度和串口带宽检查。

### 12.2 硬件分阶段验证

1. GPS 静态：10 Hz、坐标漂移、卫星数、HDOP、失效和恢复；
2. 赛前测点重复性：同一点多次测量并记录离散范围；
3. 相机标定：蓝色背景、KT 板和红色赛道上的白框；
4. 视觉测距：中心和边线距离误差不超过 5 cm；
5. 单雷区低速：进框、±10 cm 居中、750° 旋转和退出；
6. 边界故障：遮挡相机、模拟位姿跳变、断开 GPS 和 IMU；
7. 多雷区：按固定路线依次完成全部目标；
8. 全流程：从发车区出发、完成全部雷区、进入掉头区并返回。

### 12.3 最终验收条件

- GPS 只用于到达视觉接管区域；
- 每次旋转前车辆中心误差不超过 10 cm；
- 左右轮迹始终不越过白框内边界；
- 每个雷区有效累计旋转不少于 720°，软件门限为 750°；
- 任一关键传感器失效时车辆及时停止；
- 全部雷区完成并返回发车区；
- 遥测能够复原每次状态转换、定位质量、最小边界距离和旋转角度。

## 13. 实施顺序

1. TAU1201 独立串口与 Satrack 验证；
2. `sensor_gnss` 快照和 VOFA+ 任务遥测；
3. 赛前测点工具和局部坐标转换；
4. 白框离线检测与相机地面标定；
5. CM7_0 位姿快照与 CM7_1 视觉融合；
6. 单雷区进框、居中、旋转与退出；
7. 固定场地图和多雷区状态机；
8. 故障注入、低速全流程和最终验收。

在完成前一阶段的静态、构建和电机关闭验证之前，不进入下一阶段的运动测试。
